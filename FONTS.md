# Typography

The site self-hosts exactly two brand families:

| Family | Source | Shipped as |
| --- | --- | --- |
| **Public Sans** | `PublicSans[wght].ttf` (variable, 100–900), pinned to a Google Fonts commit | variable, axis limited to `wght 400–700` |
| **Instrument Serif** | `InstrumentSerif-Regular.woff2` (static 400), pinned to the upstream repo | static 400 |

KaTeX ships its own math fonts and is untouched.

Everything is generated by hand and committed — the Astro build never subsets,
converts, or downloads a font. The files live in `src/assets/fonts/`, the
`@font-face` rules in `src/styles/fonts.css`, and `src/layouts/Layout.astro`
preloads the two core files.

## Files

| File | Bytes | Role |
| --- | --- | --- |
| `public-sans-core.woff2` | 14,556 | preloaded: ASCII + punctuation every layout uses |
| `public-sans-ext.woff2` | 15,948 | on demand: rest of Latin-1 + Latin Extended-A |
| `instrument-serif-core.woff2` | 10,432 | preloaded, same character set as above |
| `instrument-serif-ext.woff2` | 8,952 | on demand, same character set as above |

**Core** is `U+0020–007E`, NBSP, `©`, `·`, en/em dash, `‘ ’ “ ” „ ‟`, ellipsis,
and the combining macron/diaeresis. `©` is in every footer and `·` on 289 of
430 pages, so they belong in the preloaded file; everything else in core is
ordinary body-text punctuation.

**Ext** is the rest of Latin-1 plus Latin Extended-A plus the handful of used
characters outside those blocks (`•`, `−`, `ṅ`, `₹`). A character the source
font does not have simply does not appear in that family's ext file.

Both `unicode-range` values are generated from each file's actual `cmap`, so the
two files never claim the same code point and neither claims a character it
cannot render. Characters only system fonts can draw (`→`, `➢`, `𝜋`, CJK,
Devanagari) are deliberately absent: they keep falling back exactly as before.

OpenType features kept: Public Sans `ccmp locl liga calt kern tnum lnum mark
mkmk`; Instrument Serif `ccmp locl liga kern mark mkmk`. Hinting is dropped, as
it already was in the Google subsets. `font-display` is still `swap`, and no
`local()` or generated fallback face sits between core and ext.

The font binaries keep their upstream internal names (the OFL texts declare no
Reserved Font Name, so renaming is neither needed nor done). Public Sans is
still named "Public Sans Thin" inside; the CSS descriptors set the family name
and weight range, which is all a browser matches on.

## Measured result

Old files were the Google `latin` + `latin-ext` subsets (still in git history:
`public-sans-latin*.woff2`, `instrument-serif-latin*.woff2`).

| | Before | Now |
| --- | --- | --- |
| Public Sans | 45,008 B | 30,504 B (−32.2%) |
| Instrument Serif | 22,868 B | 19,384 B (−15.2%) |
| Preloaded per page | 41,676 B | 24,988 B (−40.0%) |

Across all 430 built pages (font requests recorded from a real browser):

| Pages | What loads | Bytes |
| --- | --- | --- |
| 375 (87%) | both core files | 24,988 |
| 55 (13%) | both cores + Public Sans ext | 40,936 |
| 0 | Instrument Serif ext | — |

Average 27,027 B/page against 41,676 B before (−35.2%). The 55 pages that pay
for ext contain `° • é ṅ ²` and friends in Public Sans text; they come out only
1.8% lighter than the old single file, which is the accepted cost of the split.

## Rendering differences

Same source, same viewport (1440×1000, DPR 1), before/after pixel diff:

| Page | differing pixels | above 32/255 |
| --- | --- | --- |
| home | 0.86% | 0.07% |
| syllabus/cse/3 | 1.83% | 0.49% |
| calculator | 0.86% | 0.12% |
| holidays calendar | 4.43% | 0.09% |
| data-browser | 0.16% | 0.01% |
| pyq / oop (two slices) | 2.04% / 2.88% | 0.50% / 0.81% |
| pyq / english (three slices) | 2.09% / 3.67% / 2.83% | 0.49% / 1.03% / 0.78% |

All of it is anti-aliasing on glyph edges. Advances at 400 are identical to the
old files and to the source; instancing rounds outlines by at most 0.5 font
units, so edges re-rasterize a fraction of a pixel and text-sized boxes differ
by ≤0.2 px. Element rects match to 0.01 px on every sampled page.

One real reflow: `/pyqs/object-oriented-programming/` is 59 px shorter, because
two long lines wrap one word earlier. Limiting the axis to 400–700 rebases the
variation deltas, which moves 700-weight advances by up to 10/1000 em (a 42,863
unit label becomes 42,873) — enough to push those two lines past the column
edge. Removing that difference means shipping the full 100–900 axis, which
costs +3,216 B; the axis limit is the point, so this is accepted.

## Regenerating

```sh
uv run scripts/subset-fonts.py                  # download pinned sources, rewrite fonts + CSS
uv run scripts/subset-fonts.py --source-dir DIR # offline, DIR holds the two source files
uv run scripts/subset-fonts.py --check          # verify committed files match, exit 1 if not
```

The script pins both source URLs and their SHA-256 hashes, so a changed upstream
file fails loudly instead of silently producing different fonts. Output is
byte-stable: `head.modified` is copied from the source (`recalcTimestamp =
False`), so two runs are identical and `--check` is meaningful.

Rerun it only when:

- the Latin-1 / Latin Extended-A requirement changes,
- a page starts using a character outside the sets above — add it to `USED` in
  the script, never by hand-editing `fonts.css`,
- an upstream font file changes (update the URL and hash together),
- the CSS feature list changes.

Then rebuild and commit the four `.woff2` files plus `src/styles/fonts.css`.
